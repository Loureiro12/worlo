# Internacionalização (`@worlo/i18n`)

- **pt-BR é a fonte da verdade** (`packages/i18n/src/locales/pt-BR/`), com o texto exato do handoff (`docs/06_COPY.md`). `en` e `es` são tipados contra ela: chave faltando ou sobrando quebra o `typecheck`.
- **Um módulo por área do app**, iguais nos três idiomas: `common`, `languages`, `auth`, `tripForm`, `explore`, `map`, `trips`, `planning`, `community`, `profile`, `discovery`, `share`. Cada área edita só o seu arquivo.
- `t()` é tipado no monorepo inteiro: `t('explore.titel')` não compila.
- O teste `i18n.test.ts` garante, para cada idioma: mesmas chaves, nenhuma string vazia e as mesmas variáveis de interpolação.
- **Plural** usa os sufixos do i18next (`_one`, `_other`): `t('common.count.countries', { count })`.
- **Conteúdo não é traduzido.** Nomes de lugares, posts e viagens dos mocks são dados do usuário e ficam no idioma original.

## Idioma em uso

1. Preferência salva (Configurações › Idioma), lida de forma síncrona no boot.
2. Senão, o melhor match com os idiomas do aparelho (`expo-localization`), respeitando a ordem do usuário: `pt-PT → pt-BR`, `es-MX → es`.
3. Senão, `pt-BR`.

## Adicionando textos

Adicione a chave no módulo da área em `locales/pt-BR/<área>.ts`. O typecheck aponta os arquivos `en`/`es` que precisam dela. Nunca coloque texto visível fixo em componentes. Para erros de domínio, lance um código e traduza na UI.
