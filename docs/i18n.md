# Internacionalização (`@worlo/i18n`)

- **pt-BR é a fonte da verdade** (`packages/i18n/src/locales/pt-BR.ts`). `en` e `es` são tipados contra ela: chave faltando ou sobrando quebra o `typecheck`.
- `t()` é tipado no monorepo inteiro: `t('tasks.titel')` não compila.
- O teste `i18n.test.ts` garante, para cada idioma: mesmas chaves, nenhuma string vazia e as mesmas variáveis de interpolação (`{{count}}`, `{{title}}`).
- **Plural** usa os sufixos do i18next (`_one`, `_other`) com `Intl.PluralRules`: `t('tasks.remaining', { count })`.

## Idioma em uso

1. Preferência salva pelo usuário (Configurações), lida de forma síncrona no boot, sem flash de idioma errado.
2. Senão, o melhor match com os idiomas do dispositivo (`expo-localization`), na ordem do usuário: `pt-PT → pt-BR`, `es-MX → es`.
3. Senão, `pt-BR`.

## Adicionando um idioma

1. `locales/<tag>.ts` tipado com `TranslationSchema`.
2. Registre em `resources` (`src/index.ts`) e em `languages.*` nos três arquivos.
3. Inclua o tag em `supportedLocales` no `apps/mobile/app.config.ts`.

## Adicionando textos

Adicione a chave em `pt-BR.ts`. O typecheck vai apontar os outros idiomas que precisam dela. Nunca coloque texto visível hardcoded em componentes. Para mensagens de erro de domínio, lance um código (como `TaskValidationError('titleRequired')`) e traduza na UI.
